# 简历优化流程参考

## 参考来源

- [Resume Matcher](https://github.com/srbhr/resume-matcher)：采用主简历、岗位描述、定制内容、人工修改和 PDF 导出的分层流程。
- [JSON Resume](https://github.com/jsonresume/jsonresume.org)：用社区约定的结构化 Schema 表达基础信息、经历、教育、技能和项目，便于校验和多模板渲染。

## 在本项目中的落地

| 阶段 | 设计 | 目的 |
| --- | --- | --- |
| 主事实 | Markdown 原文保存为 `evidence`，抽取结果保存为一条 `project` 事实 | 让简历内容可回溯，不把标题、角色和正文拆散 |
| 结构化提炼 | `summary`、`role`、`tech_stack`、`highlights`、`evidence_map` 分栏保存 | 让前端可以逐字段编辑，定制简历可以按模块重排 |
| 证据门禁 | 每条要点关联连续原文片段，覆盖率不足时标记待核对 | 降低模型编造数字、技术和成果的风险 |
| 岗位定制 | 只从确认事实中按真实 JD 选择和重排内容 | 同一份主简历可以生成不同岗位版本 |
| 人工编辑 | 用户可以修改摘要、角色、技术栈和要点，再保存版本 | 保留用户判断，不把 LLM 输出当最终事实 |
| 渲染与质量 | 结构化数据经过 Schema 校验后再进入简历预览和 PDF | 避免抽取层、编辑器和渲染层各自维护一套文本 |

## 与通用 Agent 的解耦

该 Skill 只负责“文档 → 可核查项目事实”，不负责面试追问、代码执行、岗位出题或评分。它可以被事实库上传流程调用，也可以被定制简历流程复用；未来增加 ATS 分析时，应以已确认事实和真实 JD 作为输入，而不是把 ATS 关键词直接写回事实库。
