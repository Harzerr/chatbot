# 2026-08-15 工作记录

## 面试问答、结束状态与评估链路修复

### 1. 修复的问题

- 代码题或代码题追问在前端可能连续显示两次。
- “不清楚 / 不会”等回答的答题计数与报告中的有效作答数不一致。
- 达到面试题数上限后，后端仍可能先调用模型生成下一道问题，前端出现多余问题或覆盖结束提示。
- 面试结束后原问答区域被隐藏，用户无法继续查看完整对话。
- 评估任务因 `knowledge_context_cache_hit` 参数未在 `EvaluationAgent.evaluate_answer` 中兼容而失败。
- 评估页面在评估失败或任务卡住时只能刷新，无法重新把旧问答加入评估队列。
- 非有效回答会导致报告问答链断裂，代码题之前的问答看起来像消失。

### 2. 实现调整

| 位置 | 修改 |
| --- | --- |
| `app/services/interview_skill.py` | 在最后一道有效回答后跳过提问模型调用，直接返回“面试已结束”；最终回答仍正常进入评估队列。 |
| `app/agent/evaluation_agent.py` | `evaluate_answer` 增加 `knowledge_context_cache_hit` 参数并传入 `EvaluationRequest`，兼容新版评估请求。 |
| `app/api/endpoints/chat_history.py` | 原评估重试接口不再只允许失败/降级结果，允许对已完成题目重新入队，用于验证新的 Prompt、证据解析和评分逻辑。 |
| `frontend/src/pages/InterviewEvaluation.js` | 为每道题增加“重新评估本题 / 重新入队”按钮；失败、处理中和已完成状态均可触发。 |
| `frontend/src/pages/Chat.js` | 过滤连续重复的 AI 消息；答题数只统计 `answer_counted !== false` 的回答；结束后保留问答界面并提示用户进入评估。 |
| `app/services/interview_report.py` | 报告保留非有效回答对应的问答记录；这类回答不计入有效答题数，但不会删除其前置代码题或问答上下文。 |

### 3. 计数口径

- 有效答题数由后端 `answer_counted` 与 `is_countable_answer` 共同决定。
- “不清楚”“不会”等明确无法回答的内容保留在问答记录中，但 `answer_counted=false`，不进入有效答题数和评分题数。
- 报告展示的问答条数与有效答题数分离：前者用于完整复盘，后者用于综合评分和面试进度。

### 4. 结束状态行为

最后一道有效回答提交后，系统不再调用提问模型，不会生成下一道问题，直接返回结束提示。前端保留完整历史问答，并展示“本场面试已结束……请点击右侧‘进行评估’”提示；右侧按钮切换为“进行评估”。

### 5. 评估重新入队流程

```text
评估页点击“重新评估本题”
  -> POST /api/v1/history/chats/{chat_id}/messages/{point_id}/evaluation/retry
  -> 读取原始问题、回答、简历、技术资料和代码运行结果
  -> 更新题目状态为 queued
  -> 投递 interview_evaluation 队列
  -> Worker 重新调用 InterviewEvaluator
  -> 页面轮询并展示新结果
```

重新评估不会改变候选人的原始回答，也不会伪造新的 RAG 证据。

## 评估页无限加载体验修复

### 问题与根因

进入 `/chat/{chat_id}/evaluation` 后页面一直显示全屏转圈。原因是首次请求报告时调用了 `loadReport(true)`，其中 `true` 表示静默请求，而静默分支不会执行 `setLoading(false)`，导致页面的 `loading` 状态永久保持为 `true`。此外，原页面把报告接口响应作为页面渲染前置条件，评估或参考答案生成较慢时用户无法看到任何问答内容。

### 调整

- `frontend/src/pages/InterviewEvaluation.js` 不再根据 `loading` 返回全屏 Spinner。
- 页面先渲染评估页面框架和空的问答列表，报告请求在后台执行。
- 首次请求恢复使用非静默模式，确保请求结束后正确清除 `loading` 状态。
- 报告接口统一使用轻量 `partial=true` 请求，不等待参考答案生成。
- 请求增加 15 秒超时；超时后展示明确错误和刷新/重新评估操作，不再无限等待。
- 评估中的 Spinner 仅保留在具体题目内，不阻塞整个评估页面。

### 用户体验结果

进入评估页后可以立即看到页面结构和已有问答；评估队列、模型延迟或报告生成不会阻塞页面导航。评估失败、超时和处理中状态均有明确提示，并可以继续刷新或重新入队。
